# ConstructEase API

Backend for ConstructEase: purchase orders, goods receipts, stock, labour attendance, payments, worklog and reports for construction sites.

TypeScript · Express 5 · MongoDB (replica set) · zod. Two processes from one codebase: the **API** (`src/server.ts`) and the **worker** (`src/worker.ts`) that renders PDFs, builds Excel exports and geocodes check-ins.

- Contract: [`docs/API.md`](docs/API.md)
- Conventions for contributors: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)
- Moving data from the old app: [`docs/MIGRATION.md`](docs/MIGRATION.md)

## Run locally

```bash
npm install
cp .env.example .env                       # fill in JWT_ACCESS_SECRET (openssl rand -base64 48)
docker run -d -p 27017:27017 --name ce-mongo mongo:7 --replSet rs0
docker exec ce-mongo mongosh --quiet --eval "rs.initiate()"
npm run dev                                # API on :8000
npm run dev:worker                         # jobs (PDF/Excel need PDF_BROWSER_WS_ENDPOINT or CHROME_PATH)
CE_OWNER_PASSWORD='<password>' npm run org:create -- --org "Acme Builders" --name "Owner Name" --email owner@example.com
```

Or the whole stack: `JWT_ACCESS_SECRET=$(openssl rand -base64 48) docker compose up --build`.

### Database

Use a **new, empty database** for this version and name it in the URI (`…/constructease?…`). Without a name MongoDB uses `test`, which is where the old app keeps its data. The old app and this one share six collection names (`sites`, `products`, `notes`, `payments`, `purchaseorders`, `purchasereturns`) with different shapes, so the API refuses to start on a database that still has old-app data. Copy old data across with `npm run migrate:legacy` (see docs/MIGRATION.md); the old database is only read.

## Deploy (Render)

`render.yaml` is a Render Blueprint: one Docker web service that runs the API and the background jobs (PDFs, Excel exports). The image includes Chromium and Noto fonts, so PDFs need no external service.

1. Render → **New → Blueprint** → this repo, branch `dev`.
2. Fill the two secret values it asks for:
   - `MONGODB_URI`: MongoDB Atlas, **with a new database name** (`…mongodb.net/constructease?retryWrites=true&w=majority`). In Atlas → Network Access, allow Render's outbound IPs (or `0.0.0.0/0` with a strong password).
   - `CORS_ORIGINS`: the web app URL, e.g. `https://constructease.vercel.app`.
   `JWT_ACCESS_SECRET` is generated by Render.
3. After the first deploy, open the service's **Shell** and create the first organisation:
   `CE_OWNER_PASSWORD='<password>' node dist/scripts/create-org.js …` is not bundled — instead run it from your machine against the same `MONGODB_URI`:
   `CE_OWNER_PASSWORD='<password>' MONGODB_URI='<atlas uri>' npm run org:create -- --org "…" --name "…" --email …`
   or migrate the old data: `MONGODB_URI='<atlas uri>' npm run migrate:legacy -- --source-uri "<old uri>" --dry-run`, then without `--dry-run`.
4. In the web app's `vercel.json`, forward `/api/:path*` to `https://<service>.onrender.com/api/:path*`.

Notes: `TRUST_PROXY=2` because requests pass through Vercel's rewrite and Render's proxy (it makes login rate limits per real user, not per proxy). The `starter` plan is recommended; `free` works but sleeps after 15 idle minutes. For heavier PDF/export load, add a Render **Background Worker** from the same image with start command `node dist/worker.js` and set `RUN_JOBS_IN_API=false` on the web service.

Any other container host works the same way: run the image as the API (default command) and optionally as a worker (`node dist/worker.js`). It needs `MONGODB_URI` (a replica set) and `JWT_ACCESS_SECRET`. Serverless platforms are not supported.
